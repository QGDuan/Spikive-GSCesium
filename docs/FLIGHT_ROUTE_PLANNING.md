# 无人机飞行路线、体素避障与数据闭环

## 1. 实现边界

飞行路线是与“场景”“标签”平级的独立业务模块。历史 Git 中的旧规划器只用于提取安全原则；当前实现没有搬回 Cesium/AHoLo、旧任务 JSON、旧 Home 参数或旧渲染逻辑，而是在现有 PlayCanvas + SQLite + SVO 架构中重新实现。

职责只有三层：

- React 航线页负责起点、顺序标签、参数、计算和删除交互；
- Node 后端负责航线持久化、观察点生成、体素避障和最终复检；
- PlayCanvas 只显示规划结果的点和线，不参与路线正确性判断。

## 2. 数据关系

SQLite schema v3 新增：

- `missions`：场景、名称、必选起点、五个飞行参数、状态、碰撞版本和错误；
- `mission_labels`：按 `sequence` 保存用户指定的巡检标签顺序；
- `waypoints`：保存起点、巡检点、途经点、局部坐标、姿态、速度、目标标签、净空和复检结果；
- `label_references`：使用 `mission-start` 和 `mission-target` 记录航线对标签的引用。

因此约束由后端和数据库共同保证：

1. 航线、起点和巡检标签必须属于同一个场景；
2. 一个场景可没有起点标签，但建立航线时必须已有且指定唯一的“起点”；
3. 被航线引用的起点或巡检标签不可删除，使用中的起点也不可改成其他类型；
4. 删除航线会释放全部标签引用；
5. 永久删除场景时按“航线及引用 → 标签 → 场景文件”顺序清理；
6. 体素 revision 改变时，旧航点会被清空，航线回到待规划状态；标签位置和法向不受体素重算影响。

## 3. 参数契约

每条航线保存以下参数，输入可由用户任意指定，不使用预设档位：

| 参数 | 单位 | 规则 |
|---|---:|---|
| `speed` | m/s | 大于 0 |
| `inflationRadius` | m | 大于 0；作为全链路唯一无人机膨胀系数 |
| `observationDistance` | m | 大于 0 |
| `minimumSpacing` | m | 不小于 0 |
| `maximumSpacing` | m | 大于 0，且不小于最小点间距 |

所有值只接受整数或一位小数，后端再次校验，前端 `step=0.1` 只是输入辅助。最大点间距用于细分过长航段，最小点间距只允许在快捷连线也通过同一膨胀扫掠时删除过近的自动途经点。

## 4. 观察点生成

数据库中的标签点是被观察表面点，不是无人机可直接飞到的航点。对位置 `P`、朝外单位法向 `N` 和观察距离 `d`，名义观察点为：

```text
O = P + N × d
观察方向 = normalize(P - O)
```

以上规则只用于巡检标签。系统先检查该名义点。若其膨胀净空或到表面的视线不通过，再在朝外法向一侧尝试有限的倾角和 `1.0 / 1.15 / 1.3 / 1.5` 距离倍率；不会搜索法向背面。候选必须同时满足：

- 以 `inflationRadius` 做球体净空检测；
- 从标签沿法向外侧、最多四个体素范围内找到的第一个自由采样点，与观察点之间的零半径视线无阻挡；
- 在安全候选中优先法向一致性，再兼顾与上一节点的距离。

起点不是被观察对象，采用独立的法向起飞规则：

```text
takeoff = start.position + normalize(start.normal) × 1.5m
```

起点的法向就是起飞方向，不使用任务的观察距离，不做观察视线判断，也不让起飞航点朝回起点标签。起飞位置必须满足无人机膨胀净空；除起点表面附近一个受控体素余量外，沿法向到 1.5m 的完整通道必须通过同一膨胀扫掠。路线从该起飞航点出发，按用户顺序访问观察点，最后回到同一个起飞航点。

标签位置来自可见 GS 前表面，而保守体素化可能在该表面周围占用多个离散采样。巡检视线终点因此不是固定偏移量：规划器以半体素步长沿持久化法向寻找第一个自由采样点，但搜索上限严格为四个体素。超过该厚度仍未离开占用区即拒绝标签，不会穿过厚墙寻找另一侧自由空间。

## 5. 源 PLY 与体素坐标边界

持久化标签、航点和路线全部采用视觉 SOG 对应的源 PLY 局部 Z-up 坐标。`splat-transform` 的 PLY 格式约定包含 `Rz(180°)`，官方 voxel/GLB 输出则烘焙到 identity 坐标。因此 `VoxelWorld` 在唯一存储边界执行：

```text
voxel = (-source.x, -source.y, source.z)
```

该变换是自逆刚性旋转，不改变长度、膨胀球或点间距。规划器、SQLite 和 PlayCanvas 路线 Overlay 不得看到体素内部坐标；调试 GLB 使用同一旋转适配后才能和 GS 重合。

## 6. 避障与复检

每个相邻目标执行统一流程：

1. 先用 SVO 对整段做膨胀球扫掠；
2. 直线不通时，在局部搜索范围使用 26 邻域 A*；
3. A* 不只检查候选端点，每一条对角边也执行连续膨胀扫掠，禁止穿角；
4. 路径平滑只能采用已经通过同一扫掠规则的快捷线；
5. 删除过近途经点后，再按最大点间距插入蓝色途经点；
6. 最后逐点检查膨胀净空、逐段检查膨胀扫掠，并重新计算姿态和净空。

SVO 把占用体素当作实体立方体。球体与体素 AABB 做保守相交；航段按不大于半个体素的间隔采样，规划、细分和最终复检使用同一规则。体素边界外属于未知空间，按不可通行处理。

A* 最多展开 150,000 个节点，最终航点最多 5,000 个。完整复检通过才是 `valid`；失败时可以保留失败位置之前的安全前缀用于人工诊断，但状态仍为 `invalid`，不得导出或执行。

节点预算是资源保护，不是“数学上无路”的证明。搜索结果因此区分 `blocked-endpoint` / `unreachable` / `expansion-limit`：只有 `found` 加最终复检可以证明当前候选航线有效；`expansion-limit` 仅表示有界搜索未完成连通性判定。当前均匀 26 邻域网格是有界离散规划器，不声称对任意尺度场景具有连续空间完备性。后续自适应 Octree/分层规划必须保留同一 SVO 膨胀和最终逐段复检，不得通过当前场景的固定升高或坐标绕行规则规避问题。

## 7. API

- `GET /api/datasets/:datasetId/missions`：当前场景航线列表；
- `POST /api/datasets/:datasetId/missions`：建立待规划航线；
- `GET /api/missions/:id`：读取单条航线与航点；
- `PATCH /api/missions/:id`：修改名称、起点、标签顺序或参数，并清空旧航点；
- `POST /api/missions/:id/plan`：使用当前活动碰撞 revision 规划；
- `DELETE /api/missions/:id`：删除航线并释放标签引用。

规划失败是有效业务结果，接口仍返回保存后的 `invalid` 航线及安全前缀，而不是把它伪装成网络错误。

## 8. 可视化与生命周期

- 起点和巡检观察节点：红色世界空间 Mesh；
- 自动绕障和间距细分节点：蓝色世界空间 Mesh；
- 有效完整路线：绿色深度测试线段；
- 无效安全前缀：橙色深度测试线段。

路线 Overlay 是当前唯一 PlayCanvas 场景根节点的子树。场景切换、清除、航线删除和 Application 销毁都会先销毁该子树；共享材质只在 Application 最终销毁时释放。标签前表面 Picker 准备拾取缓冲时会临时排除路线 Overlay，避免点线影响 GS 或标签拾取。

## 9. 验收重点

- 没有起点、跨场景标签、重复标签、旧视觉标签或缺少法向时拒绝建立/规划；
- 标签被起点或目标引用时，标签页显示“使用中”且后端删除返回冲突；
- 体素重算后旧航点不再显示为有效；
- 起飞节点固定为起点沿自身法向 1.5m，不读取观察距离；巡检观察节点才按观察距离生成并朝向标签；
- 源 PLY 坐标经 `Rz(180°)` 查询当前 SVO 后，起飞通道、观察视线、A* 和最终复检使用同一坐标适配；
- 最大/最小点间距、速度和膨胀系数持久化值与输入一致；
- 有效路线和失败安全前缀状态、颜色和可执行语义不可混淆；
- 删除航线后引用释放，删除场景后航线、标签和文件全部清理。
