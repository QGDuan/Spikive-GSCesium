# 架构与方案总结

## 1. 决策摘要

本系统采用“显示模型与碰撞模型分离”的方案。Cesium Gaussian 3D Tiles 与候选 AHoLo Chunk LOD 负责照片级显示；稀疏体素负责占用判断、表面解析和路径规划。原因是 GS 属于半透明渲染表示，任一前端 Renderer 的深度都不能作为无人机碰撞安全依据。

核心语义固定为：

```text
PLY
 ├─ Gaussian 3D Tiles ── Cesium 回滚/地图显示 ─┐
 ├─ AHoLo Chunk LOD ── 本地巡检候选显示 ──────┼─ 相机射线 → SVO 手动拾取标签
 └─ SVO/Collision GLB ── 法向解析 ── 观察点生成 ── 三维避障航迹
```

## 2. 组件

- `apps/web`：React、CesiumJS、AHoLoJS、tus-js-client；负责上传、互斥 Renderer、标签拾取和路线呈现。
- `apps/server`：Fastify、Node SQLite、后台 worker、体素查询和路径规划。
- `packages/shared`：Zod 输入契约、公共类型和向量运算。
- `3dgs-ply-3dtiles-converter`：PLY → 分层 SPZ Gaussian 3D Tiles。
- `splat-transform`：PLY → SVO 体素与 collision GLB。
- `@manycore/aholo-splat-transform`：PLY → 无损 Chunk LOD → 逐 Chunk 高精度 ESZ。

平台为单机可部署 MVP：SQLite、磁盘存储和单并发 GPU worker。单机路径清晰、可恢复，未来可将 worker、对象存储和数据库替换为 Redis/MinIO/PostgreSQL，而不改变前端接口语义。

SQLite 固定使用 WAL。连接初始化必须先设置 `busy_timeout`，再读取当前 journal mode，只在尚未启用 WAL 时切换，避免开发期 watch 连续重启时新旧进程短暂重叠而争抢 journal 配置锁；初始化或迁移失败时立即关闭刚创建的连接。API watcher 忽略 `packages/shared/dist/**` 和只服务于前端的 Cesium 包：根级 `predev` 已先构建共享包，验证、生产构建和确定性 Shader 补丁不应重启正在运行的 API。Fastify 关闭时回收空闲 keep-alive 连接并等待活动请求完成，避免新进程绑定 3000 端口时产生短暂 `EADDRINUSE`。

## 3. 数据与状态流

数据集状态：

```text
created → uploading → queued → tiling → collision_processing → ready
                                      └──────────────────────→ failed → retry
ready → rebuilding visual tiles → ready（期间继续提供上一发布版本）
ready → rebuilding AHoLo candidate → ready（期间生产 Renderer 不变）
```

上传完成后，原始 PLY 移到不可由文件名控制的 UUID 路径。转换器通过参数数组启动，未使用 shell。两个产物都完成后才将工作目录原子发布；进程重启会把处理中状态恢复为排队状态。

碰撞任务失败时保留工作目录中的已完成切片。人工调整碰撞参数并重试后，Worker 只有在 `tileset.json` 和固定 LOD `build_summary.json` 均重新验收通过时才复用 Gaussian 3D Tiles；否则从源 PLY 重建。碰撞子进程每次退出后由操作系统回收其 CPU/GPU 资源，半成品碰撞目录会在下一次尝试前清空。

3D Tiles 保持模型局部坐标。服务端返回 `tileset.json` 时注入 ENU/WGS84 根矩阵，标签和航迹均存模型局部 XYZ，因此修改数据集定位不会破坏绑定关系。

转换器会在 `build_summary.json` 审计源轴向。碰撞 Worker 读取该结果，将 camera Y-down/Z-forward、glTF Y-up 或原生 Z-up 自动归一到与 3D Tiles 相同的局部 Z-up 坐标；无法识别轴向时任务失败，禁止发布错位产物。

Gaussian LOD 不固定层数。V2.1 高清档固定最细分区 25,000 Gaussian、普通切分停止阈值 2,500、父层 0.65 采样率、`max` 基础曲线、1.35 coarse-layer multiplier、2.5 global geometric-error scale、0.6 覆盖补偿和 0.02 透明度过滤；最大逻辑深度根据有效 Gaussian 数量自适应。当前 14.22M 输入由11层增至16层、约602 MiB，且仍由Cesium按视锥和SSE局部请求。稳定浏览SSE固定16、动态SSE关闭、有效像素比上限1.5，缓存保持384 MiB + 128 MiB。完整公式与验收见 [GS LOD 与初始化展示固定策略](LOD_AND_INTRO.md)。

已发布模型可执行可视化专用高清重建：不可变源 PLY 重新生成 Tiles，原碰撞制品只做完整性与摘要校验，标签和航迹不失效。重建期间活动视觉 revision 继续服务；新 revision 验收后只原子切换 artifact manifest，并将旧活动版保留七天。碰撞目录不会被复制、替换或重新加载，版本化 Tile URI 也避免浏览器混用新旧 GLB。这个流程不重复运行碰撞生成，也不自动调整任何碰撞参数。

AHoLo 候选拥有独立工作目录、manifest 和 revision。唯一 LOD 拓扑先从不可变源 PLY 生成无损 PLY Chunk，再逐 Chunk 编码 ESZ v2；每个 Chunk 写完后释放解码资源，保证 ESZ 与对照 PLY 的块、点数和层级一一对应。候选验收成功不自动切换生产 Renderer，只有显式操作才改变 `visualBackend`。AHoLo 只接管显示、相机射线和覆盖物：射线仍提交后端 SVO，法向、标签吸附、体素碰撞和航迹规划没有前端副本。会话面板通过公开 `LodSplat.setConfig()` 显式调整 LOD/minLevel/预算与调度参数，不持久化、不自动降质，也不改变任何碰撞或任务 revision。完整契约见 [AHoLo Renderer 迁移与验收](AHOLO_RENDERER_MIGRATION.md)。

首次加载的 Luma 风格效果属于纯展示依赖：公开的 Tileset 参数继续负责 LOD 请求，一个版本锁定且可验证的 Cesium Gaussian Shader 扩展只在输入锁定的 20 秒内把已加载高斯从中心种子扩张为完整椭球。应用通过独立控制器与该扩展通信，不访问 Cesium 私有 Primitive；退出后重建回原始 Shader。Reveal 不产生第二份 GS、不参与碰撞和路径规划，也不能改变标签/任务的数据依赖。它不是第二套渲染系统：同一时刻仍只有一个 Viewer、一个 Gaussian Primitive、一个 DrawCommand 和一个活动 ShaderProgram。为何保留阶段性 Shader 变体而不改成永久组合 Shader，见 [Cesium GS Reveal 渲染架构决策](CESIUM_GS_RENDERING.md)。

### 数据工程闭环

数据集是工程聚合根，不把 SQLite 记录和磁盘目录当成互不相关的两套数据。依赖方向固定为：

```text
源 PLY 版本
  ├─ 坐标/尺度审计
  ├─ Gaussian Tiles 产物版本
  └─ Collision 产物版本
       └─ 标签几何/法向版本
            └─ 航迹任务版本
```

数据管理闭环覆盖“上传临时态 → 完整性与坐标校验 → 不可变源数据 → 隔离派生 → 产物验收 → 原子发布 → 依赖绑定 → 失效传播 → 重建 → 监控/备份 → 按依赖删除”。源 PLY 与数据库元数据属于不可替代资产；Tiles 和碰撞体只有在保存了源版本、工具版本、固定策略、参数和构建摘要时才可视为可重建资产。

当前系统已实现 UUID 路径、处理状态、源/Tiles/碰撞校验摘要、视觉 artifact revision、LOD 质量报告、活动 manifest、七天上一版本保留、数据库外键级联和标签/任务失效传播。`npm run audit:data` 对账 SQLite、活动 manifest、跨场景引用、ready 制品及孤儿数据。视觉 revision 与碰撞 revision 独立：只有源或碰撞语义变化才向标签和任务传播失效，纯视觉重建不传播。任何自动清理只处理明确过期且非活动的视觉 revision；歧义数据只报告，不猜测修复。

### 碰撞内存与分区边界

当前 `splat-transform 3.1.6` 的 `.voxel.json` 路径按全场构建一个 SVO。室外 floor fill、室内 external fill 和 collision mesh 都需要可变网格；CLI 没有与 Gaussian 3D Tiles 等价的原生碰撞分块流式输出参数。14.2M Gaussian 等大场景可能在约 60% 的碰撞阶段触发工具的 1 GiB 可变网格保护。这不是 GS LOD 覆盖失败，也不是服务内存泄漏。

构建在独立子进程中进行，进程结束即释放该次构建的 GPU/CPU 内存。已发布 SVO 的服务端读取缓存另设 `COLLISION_CACHE_BYTES` 字节预算（默认 512 MiB）：同一场景并发加载合并为一个 Promise，缓存按 LRU 逐出并释放 TypedArray 引用；单个 SVO 大于预算时仍允许保留当前唯一条目，因此实际上限为 `max(预算, 最大单个活跃 SVO)`。`GET /healthz` 暴露当前条目数、字节数和预算用于监控。

平台不会自动改变 `voxelSize`。命中该特定保护错误时，后台只依据工具报告计算一个更大体素尺寸的建议值并进入 `failed`；操作员必须在界面确认尺寸后才会 PATCH 参数并重试。体素尺寸越大，占用内存越低，但细线缆、边缘和小构件的召回也越弱，因此调整后必须重新做细障碍与最小净空验收。

碰撞分块可实现，但必须作为独立的安全架构升级，不能直接并行启动多个全量 CLI：

1. 一次性把源 Gaussian 空间分桶，记录稳定分区 ID、AABB、源版本和带安全余量的 halo；父进程不得为每个分区重复完整读取 PLY。
2. 默认逐区串行生成 SVO，子进程退出即释放内存；只有内存预算器证明总峰值可控时才允许有限并发。
3. 生成 collision manifest，记录分辨率、坐标系、核心区/halo、checksum 和构建状态；全部分区验收后才能原子发布。
4. `CollisionRepository` 按 AABB 索引和 LRU 加载分区；射线、扫掠球和净空查询必须合并所有相交分区并去重，不能把分区边界当成自由空间。
5. floor/external fill 与室内 seed 连通性必须有全局粗网格或等价拓扑阶段；仅靠局部 halo 会在门洞、外墙和场景边界产生错误内外判定。
6. 航迹规划验收必须加入跨分区射线、跨缝路径、边界障碍和缓存逐出回归。完成这些条件前，单体 SVO 仍是唯一安全发布格式。

## 4. 标签和航迹算法

### 标签

1. 前端确认点击对象属于当前 Gaussian tileset。
2. Cesium 相机生成世界坐标拾取射线，前端逆变换为模型局部射线；不读取实验性 Gaussian 透明深度。
3. 后端用局部射线与 SVO 求第一个自由区到占用区交点，再在邻域搜索表面并通过局部占用梯度估计法向。若相机本身位于填充碰撞体内，必须先离开初始实心区，禁止把相机附近占用点误报为点击表面；零梯度内点不得用默认法向伪装成已解析标签。
4. 保存原始 GS 点、法向、吸附误差和解析状态；原始标签位置不会被碰撞体位置替换。

交互反馈分两阶段：请求后立即在点击像素显示橙色十字；后端命中后把结果变换回世界坐标，显示带光环和中文“待保存标签”的固定屏幕尺寸点。该点只是未持久化的预览，保存、重新拾取、切换/清除场景后立即移除，不会进入航迹依赖图。

### 航迹

1. 操作员选择自由空间 Home 或一个已解析巡检标签作为起点，并提供任务飞行参数。标签起点不是标签表面坐标：规划器仍按法向、观察距离、视线和膨胀碰撞约束生成自由空间起点，任务结束后返回同一点。
2. 每个标签先按法向和观察距离生成观察点；冲突时在正反法向的完整 360° 方位、±45° 圆锥和多个距离层搜索替代点，垂直法向也必须覆盖斜向候选，并逐个验证视线与净空。
3. 占用体按“机体半径 + 安全余量”膨胀。
4. 每对固定端点先做膨胀球直线扫掠；SVO 扫掠沿航段以不超过半个碰撞体素的间距采样，并结合体素立方体半对角线膨胀，避免整体素采样的相位漏检。被阻挡时用二叉最小堆运行 26 邻域三维 A*。A* 步长固定为 `max(碰撞分辨率, 膨胀半径/2, 0.25 m)`，取消旧版无条件乘二的降采样；每一条相邻边都做同一保守扫掠，不能只检查网格端点或斜穿障碍角。
5. A* 给出当前离散网格与固定端点下的最短候选通路，再用扫掠球视线捷径缩短折线；它不擅自改变标签顺序，也不宣称是带动力学、风场或全局标签重排的绝对最优航线。
6. 折线平滑和最小航点间距删减都必须先通过扫掠球捷径检查，禁止为减少航点跨越碰撞拐点。
7. 安全折线按操作员确认的 `maximumSegmentLength`（默认 5 m）等距细分，保留 Home 或标签起点，以及 `hj_<标签名>` 检查点。标签起点通过 `startLabelId` 持久化，不得在中间巡检顺序中重复。最终所有点和每一航段再次按“机体半径 + 安全余量”复检；超过 5,000 点时任务保持 `invalid` 且不保存路线。某一后续目标无通路或最终复检中途失败时，可持久化失败位置之前严格按序复检通过的前缀，但它只用于调试可视化，保持 `invalid` 且禁止导出或执行。
8. 航点删减和细分完成后统一重算姿态：inspection 点朝向目标标签，transit/Home 点沿最终相邻航段朝向。

前端将任务建立和碰撞规划显示为连续的可观察阶段，包含运行秒数和最终成功/失败原因；任务列表每行提供计算/重新计算与永久删除入口。有效航线中所有通过 `targetLabelId` 绑定标签的点（包括标签起点）固定显示红色并保留内部语义名 `hj_<标签名>`，但不绘制重复的 `hj_` 文字；算法插入的 transit 点固定显示蓝色，自由 Home 使用中性色，绿色折线表示已通过当前碰撞模型复检。巡检对象标签在两种 Renderer 中均为可点击注记，选中高亮与详情弹窗是会话级展示状态，不修改标签、碰撞或任务。失败任务只能用橙色绘制服务端返回的已复检安全前缀，不得补齐失败点或猜测后缀，并须明确显示“部分预览、禁止导出或执行”。

体素网格外统一按未知且不可通行处理。碰撞查询还按半个体素对占用立方体做保守膨胀，避免把体素中心误当成零尺寸障碍点。

第一版保留用户选择的标签顺序，并默认返航；没有自动 TSP 排序，以避免系统擅自改变业务巡检顺序。`startLabelId` 属于与有序 `labelIds` 并列的任务依赖：删除和几何变化保护同时覆盖两者。历史任务会迁移为自由 Home 起点；缺少最大航段字段时会补为 5 m、清空旧路线并回到 `draft`，防止旧规划结果绕过新门禁。

## 5. 安全和失效条件

最可能导致错误航迹的三项因素：

| 风险事件 | 严重性 | 触发信号 | 责任人 | 处理动作 |
|---|---|---|---|---|
| 采集缺口使真实障碍未进入模型 | 高 | 标签邻域断裂、航迹贴近数据边界或现场复核发现缺面 | 建模/测绘负责人 | 禁止放飞，补采并重新转换；必要时增加显式禁入区 |
| 体素过粗使线缆等细结构消失 | 高 | 最细设施尺寸接近或小于体素尺寸 | 算法工程师与飞行安全员 | 调低体素尺寸、重新生成碰撞体并增大安全余量 |
| 源轴向、编码或尺度错误造成显示/碰撞错位 | 高 | 标签吸附距离异常、法向系统性错误或已知长度不符 | 数据工程师 | 停止发布，检查转换审计报告、GraphDECO 编码、PLY 轴向和模型单位 |

系统只生成静态数字模型上的候选路线。真实飞行前必须叠加现场勘察、飞控限制、定位误差、风、电量、禁飞区和动态障碍校验。

## 6. 演进边界

- 多用户与公网：OIDC、RBAC、审计和配额。
- 大规模并发：S3/MinIO、PostgreSQL、Redis 队列和独立 GPU worker。
- 真实任务文件：在锁定机型和飞控版本后增加 DJI WPML/KMZ 或 MAVLink adapter。
- 更严格航迹：加入机体动力学、曲率约束、能耗模型和未知空间占用策略。

## 7. 验收清单

| 能力 | 可观察的验收条件 | 执行人/时机 |
|---|---|---|
| PLY 处理与发布 | 上传测试 PLY 后状态到 `ready`，tileset、SPZ GLB、voxel JSON/BIN 均可读取 | 部署工程师，每次发布 |
| 流式显示 | Cesium Network 面板显示按视距加载多个 tile，移动视角时不下载原始 PLY | 前端测试，发布验收 |
| 初始化展示 | 首 Tile 后中心种子逐渐扩张为 Gaussian 椭球并自动环绕；期间不可拖动，正常/超时/异常退出后恢复原始 Shader 和普通操作 | 前端测试，发布验收 |
| 手动标签 | 只能点击当前 GS tileset 建点；保存后重载仍绑定原位置，法向可翻转 | 业务测试，场景验收 |
| 自动航迹 | 给定 Home、有序标签和参数，产生 Home 起止、巡检点朝向标签的线路 | 算法/业务测试，场景验收 |
| 碰撞约束 | 穿障直线被绕行或明确失败；Home/观察点冲突返回具体原因；网格外不可通行 | 算法测试，每次发布 |
| 数据交换 | JSON 与 GeoJSON 导出包含有序航点、速度、姿态、净空和目标标签 ID | 集成测试，发布验收 |

真实项目验收还必须使用客户的代表性 PLY、已知尺寸基准和人工标注障碍做对照；仓库自带的合成样本只能证明处理链可运行，不能证明真实场景安全精度。

## 8. 部署、回退与实施顺序

当前版本的交付顺序是：先用代表性数据确认坐标/尺度和细障碍可见性，再部署单机 GPU 服务，最后开展标签与航迹场景验收。只有转换链、标签绑定、碰撞回归和导出全部通过，才允许接入飞控适配层。

- 发布：执行类型检查、单元测试、生产构建和依赖审计；备份 `var/` 后替换应用镜像，保留原镜像。
- 回退：停止新上传，切回原镜像并恢复同版本数据库备份；`published/` 是可重建产物，`sources/` 和 SQLite 是必须保护的数据。
- 运行：监控磁盘、GPU 转换失败率、任务规划失败原因和异常吸附距离。单 Worker 保证 GPU 峰值可控，但形成吞吐瓶颈时再引入队列。
- 下一阶段退出条件：用目标变电站样本完成坐标与尺度基准、细线缆召回率和最小净空误差测试，并由飞行安全负责人确认机型参数；在此之前不生成 DJI/MAVLink 可执行任务。
