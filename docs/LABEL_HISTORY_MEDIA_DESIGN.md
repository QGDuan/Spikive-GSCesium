# 标签后端鲁棒性与历史图片扩展设计

## 1. 结论

当前 SQLite 标签结构适合继续作为“稳定空间目标”主表，新增的“起点”也已由数据库保证每个场景 `0..1` 个。但是，当前结构尚不能直接满足历史图片存储与展示，因为系统还没有“某次巡检”和“该次巡检的图片”这两层数据。

正确的扩展关系是：

```text
Dataset / 场景
 └─ Label / 稳定空间目标
     └─ InspectionRecord / 一次巡检事件
         └─ InspectionMedia / 该次巡检的 0..N 张图片
```

不应把图片放进 `labels` 行，不应用文件名表达历史顺序，也不应让前端自行维护图片与标签的归属关系。

## 2. 已实现的起点约束

- `起点` 是第五种固定标签类型，仍绑定场景、源 PLY 摘要和视觉 revision。
- 每个场景允许没有起点；一旦存在，最多只能有一个。
- SQLite 局部唯一索引对 `dataset_id WHERE type='起点'` 强制唯一。因此两个请求同时提交时也不会留下两个起点。
- 前端禁用重复起点选项只是交互提示；后端冲突统一返回 HTTP `409`。
- 起点可改为其他类型，或在未被任务引用时删除；之后才可建立新起点。
- 起点位置仍来自 PlayCanvas 原生前表面 Picker，不绕过现有几何来源规则。

## 3. 当前后端鲁棒性判断

| 能力 | 结论 | 保护方式 |
|---|---|---|
| 场景隔离 | 可用 | 列表、类型和空间查询均以 `dataset_id` 为首要边界 |
| 类型安全 | 鲁棒 | 应用校验与 SQLite `CHECK` 双重限制 |
| 起点唯一 | 鲁棒 | SQLite 局部唯一索引，创建和编辑冲突映射为 `409` |
| 几何可追溯 | 鲁棒 | 位置、法向、源摘要、视觉 revision 和选择证据共同保存 |
| 引用删除保护 | 可用 | `label_references` 与外键 `RESTRICT` |
| 旧库升级 | 鲁棒 | schema V2 事务迁移、`user_version`、迁移后外键复检 |
| 并发写入 | 适合当前本地单服务 | WAL、5 秒 busy timeout 和数据库唯一约束 |
| 历史图片 | 尚未满足 | 尚无巡检事件、媒体元数据、文件存储和上传 API |

当前结构适合“完全本地、单 Node 服务进程”。未来若改为多用户或多服务实例，还需增加身份和场景授权、请求幂等键，并重新评估同一 SQLite 文件的单主写入边界。

## 4. 未来历史图片数据模型

### `inspection_records`

一行表示对某个标签完成的一次巡检，至少包含：

- `id`、`dataset_id`、`label_id`；
- `observed_at`：业务发生时间，与记录写入时间分开；
- 可选 `mission_id`；
- `result`、`note`、`created_at`、`updated_at`；
- 对 `(label_id, observed_at DESC)` 和 `(dataset_id, observed_at DESC)` 建立索引。

### `inspection_media`

一行只保存一张图片的关系和可校验元数据：

- `id`、`record_id`、`dataset_id`、`storage_key`；
- `mime_type` 只接受支持的安全位图格式，不接受 SVG/HTML；
- `bytes CHECK(bytes > 0 AND bytes <= 2097152)`；
- `sha256`、`width`、`height`、`captured_at`、`created_at`；
- 外键约束巡检记录，并校验图片、记录与标签的 `dataset_id` 一致。

图片本体建议保存在受控场景目录：

```text
var/local-datasets/<dataset-uuid>/inspection-media/<media-uuid>.<controlled-ext>
```

SQLite 只保存索引、关系、大小、格式和摘要。2 MiB 以内的图片技术上也可保存为 SQLite BLOB，但随着历史增长会放大 WAL、备份和查询 I/O，因此不作为默认方案。

## 5. 上传、发布和删除闭环

1. 校验标签与场景归属，再建立巡检记录。
2. 图片先流式写入场景内临时文件；除 `Content-Length` 外，流式读取本身也硬限制 `2 * 1024 * 1024` 字节。
3. 按文件魔数验证 MIME、读取尺寸并计算 SHA-256，不信任扩展名和客户端 MIME。
4. 校验后使用服务端 UUID 文件名原子改名，再事务写入媒体元数据；数据库失败时清理已发布文件。
5. 历史列表按 `observed_at` 稳定分页。图片响应提供正确的类型、长度、`ETag` 和 `nosniff`。
6. 历史记录应计入标签引用：存在历史时默认拒绝硬删除标签，改为归档；清除历史后才允许删除。
7. 永久删除场景时，先取消活动写入，再删除所属数据库记录和 UUID 校验后的场景目录。

## 6. 后续实现验收

- 同场景并发创建两个起点，必须一成功、一返回 `409`；不同场景可各有一个。
- 旧四类型数据库升级后，标签数、几何、引用数和外键校验结果不变。
- 图片接口实现时，2 MiB 整应成功，2 MiB + 1 字节必须被流式层拒绝，失败不得留下临时文件或孤儿元数据。
- 标签与历史查询不得跨场景；非法 MIME、路径穿越、缺失文件和摘要不匹配必须明确失败。
- 备份必须同时覆盖 SQLite 一致性快照和场景 `inspection-media` 目录。
