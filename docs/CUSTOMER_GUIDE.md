# Spikive GS Inspector 客户测试使用说明

本文面向首次测试平台的客户。按照下面三部分操作即可；带“截图位置”的内容由项目经理补充实际页面截图。

> 重要提示：系统生成的是经过当前碰撞模型检查的候选航线，不等同于真实飞行许可。执行飞行前仍需结合现场、机型、法规和安全制度人工复核。

## 1. 前置条件及环境配置

### 1.1 电脑与软件

- 请按电脑下载对应安装包：
  - Apple Silicon Mac（M1/M2/M3/M4/M5）：`Spikive-GS-Inspector-*-macos-apple-silicon.zip`；
  - 64 位 Windows 10/11：`Spikive-GS-Inspector-*-windows-x64.zip`。
- Node.js `22.22.1` 或更高版本，推荐 Node.js 24 LTS，并自带 npm。
- 推荐使用最新版 Chrome 或 Edge 浏览器。
- 显卡驱动保持最新，且系统能够正常使用 WebGL2。大规模 GS 切片建议使用独立显卡或 Apple Silicon。
- 首次安装需要联网下载依赖；底图显示也需要网络。模型、标签和航线数据保存在本机。

本测试版的平台范围如下：

| 平台 | 本版状态 | 说明 |
|---|---|---|
| Apple Silicon Mac | 客户测试 | 提供 arm64 安装包，本版未做独立客户机器验收 |
| Windows 10/11 x64 | 客户测试 | 提供 x64 安装包，本版未做独立客户机器验收 |
| Intel Mac | 有限 | Cesium 路径可运行，但当前 AHoLo 原生转换依赖不提供 darwin-x64，不作为完整支持平台 |
| Windows ARM64 | 未验收 | 当前版本不提供该平台客户包 |

首次测试建议先使用非生产数据；若遇到显卡、驱动或转换工具兼容问题，请保留完整日志反馈给项目人员。

在终端中执行以下命令，能显示版本号即表示 Node.js 安装成功：

```bash
node -v
npm -v
```

### 1.2 数据与磁盘

- 输入文件必须是 GraphDECO 格式的 `.ply` Gaussian Splatting 数据。
- 单文件默认最大 5 GiB。
- 建议预留至少为源 PLY 3 倍的可用磁盘空间；大场景建议预留 10 GiB 以上。
- 运行数据默认保存在安装目录的 `var/`。备份、迁移或升级前，请先完整备份这个目录。
- 不要手工删除 `var/` 中的单个文件；删除模型、标签和任务请使用系统界面。

### 1.3 默认配置

通常不需要修改环境变量，直接使用默认值即可。

| 配置 | 默认值 | 说明 |
|---|---:|---|
| `PORT` | `3000` | 页面和 API 的访问端口 |
| `DATA_DIR` | `var` | 模型、数据库和处理产物目录 |
| `MAX_UPLOAD_BYTES` | `5368709120` | 最大上传字节数，即 5 GiB |
| `COLLISION_CACHE_BYTES` | `536870912` | 碰撞查询缓存，即 512 MiB |
| `GPU_DEVICE` | `0` | 使用的 GPU 编号 |

如果 3000 端口被占用，可在启动前设置其他端口。例如 macOS/Linux：

```bash
PORT=3100 ./start.sh
```

Windows 命令提示符：

```bat
set PORT=3100
start.cmd
```

## 2. 如何启动

### 2.1 解压与安装

1. 解压与电脑对应的 `macos-apple-silicon.zip` 或 `windows-x64.zip`。
2. 进入解压后的文件夹。
3. 根据操作系统执行安装脚本。

Apple Silicon Mac：

```bash
chmod +x install.sh start.sh
./install.sh
```

Windows：双击 `install.cmd`，或在命令提示符中执行：

```bat
install.cmd
```

安装过程需要联网，完成后会显示“安装完成”。同一版本通常只需安装一次。

### 2.2 启动系统

Apple Silicon Mac：

```bash
./start.sh
```

Windows：

```bat
start.cmd
```

看到服务启动日志后，在浏览器打开：

```text
http://localhost:3000
```

停止系统：回到启动窗口，按 `Ctrl + C`。停止服务不会删除模型、标签或航线。

## 3. 业务使用

### 3.1 上传和查看 GS 模型

1. 打开左侧“数据”。
2. 创建数据集，填写名称、场景类型和摆放信息。
3. 选择 `.ply` 文件并上传。
4. 等待“上传、切片、碰撞处理”全部完成，状态变为“就绪”。
5. 双击数据集可定位模型；可旋转、缩放和查看细节。

大场景处理可能需要较长时间。处理失败时先查看界面给出的原因；碰撞内存不足时，系统只提供体素尺寸建议，不会自动降低精度。

### 3.2 创建和查看巡检标签

1. 打开左侧“巡检标签”。
2. 点击“开始拾取”，再点击 GS 模型中需要观测的位置。
3. 系统通过碰撞数据计算空间坐标和表面法向。
4. 填写标签名称、类别和说明并保存。
5. 点击场景中的标签，可以高亮并查看坐标、法向和解析状态。

标签必须与当前 GS 数据集绑定。若标签已经被航线任务使用，需要先删除引用它的航线任务，才能删除标签。

### 3.3 创建和检查航线

1. 打开左侧“航迹规划”。
2. 选择起点：可使用自由空间 Home，也可指定一个巡检标签作为起点依据。
3. 按实际巡检顺序选择标签，并填写无人机半径、安全余量、观测距离和速度等参数。
4. 创建任务后点击“计算/重新计算”。
5. 等待碰撞检测、通路搜索和最终复检完成。

场景颜色说明：

- 红点：标签对应的观测航迹点；内部保留 `hj_标签名` 关联，但不显示重复文字。
- 蓝点：算法生成的途经点。
- 绿色线：通过当前碰撞模型复检的完整候选航线。
- 橙色线：规划失败前已复检通过的安全前缀，只用于排查，不能导出或执行。

清除显示只隐藏当前模型或航线，不删除数据。永久删除会弹出二次确认，删除后无法恢复。

## 常见问题

### 页面打不开

确认启动窗口仍在运行，并检查访问地址是否与 `PORT` 一致。也可访问 `http://localhost:3000/healthz`，正常时应返回服务状态。

### 上传一直为 0%

确认服务未停止、浏览器没有代理拦截本机请求，并重新选择该数据集上传。不要同时为同一数据集创建多个上传任务。

### 模型切片或碰撞处理失败

先保留界面中的完整错误信息。显存或碰撞内存不足时，可由技术人员评估参数；不要为了成功而随意调大体素尺寸，因为这会降低小障碍识别能力。

### 数据如何备份

先停止系统，再完整复制安装目录中的 `var/`。恢复时应使用同一版本程序并完整恢复该目录，不要只复制 SQLite 或单个模型文件。
