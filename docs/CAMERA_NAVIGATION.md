# 相机导航与巡检点近景

## 模式边界

系统只使用同一个相机，相机状态分为两个互斥模式。控制层直接组合 PlayCanvas 公开的
`KeyboardMouseSource`、`Pose` 和 `OrbitController`，不维护第二套相机：

- 第三人称：默认模式。以场景中心上方 5 米为观察焦点，默认距离 15 米、俯角 35°；拖动旋转，
  中键或 Shift 拖动平移，滚轮只改变 Orbit 距离。
- 第一人称：通过模式按钮进入时保留当前位置和水平航向，但不继承第三人称俯角，初始俯仰固定归零，
  避免进入第一人称后仍然朝下。按钮会立即申请浏览器 Pointer Lock；若浏览器拒绝，可点击场景重试。
  鼠标与 WASD 严格采用官方 `FirstPersonController` 的方向公式：`D-A` 控制左右、`W-S` 控制前后，
  移动基只读取水平航向而不读取俯仰。Q 沿世界高度抬高，E 沿世界高度降低，这是系统唯一增加的输入；
  Esc 只释放鼠标，不擅自切换模式；
  释放后可点击场景重新进入，或通过顶部按钮明确返回第三人称。

顶部图形模式标识旁的按钮显示当前模式。手动切换、加载新场景和点击巡检点都会同步控制器与
React 状态。切换模式时先解绑旧输入，再绑定新输入；销毁时同时释放 Pointer Lock、输入源和控制器。
清空显示或永久删除当前场景时，即使场景资源已经不存在，也必须先恢复第三人称并释放 Pointer Lock，
再销毁 GS、体素和标注资源；业务层随后从 Viewer 读取实际模式并同步按钮，避免“空场景仍显示第一人称”
或鼠标继续被浏览器锁定。

## 点击巡检点

普通浏览状态下单击已有巡检点 Mesh 或法向线段时：

1. 继续使用已有 PlayCanvas Picker 得到标签 ID；
2. 从当前场景标签数据读取局部 Z-up 点位 `P` 与单位法向 `N`；
3. 将相机近景位置固定为 `P + N × 4m`；
4. 将观察目标设为 `P`，因此相机观察方向为 `-N`；
5. 通过场景根变换统一转换到 PlayCanvas 世界坐标；
6. 用 PlayCanvas `Pose.look(position, target)` 建立观察姿态；
7. 将模式切换为第一人称、尝试申请鼠标锁定并立即更新顶部按钮；若异步拾取使浏览器拒绝锁定，
   点击一次场景即可重试；返回第三人称时恢复进入前保存的 Orbit 姿态。

法向缺失或退化时拒绝近景切换，不能猜测观察方向。当前阶段不增加双击表面聚焦。
点击巡检点属于法向驱动的观察动作，因此不会使用“手动切换时俯仰归零”的规则；其视线始终严格为
`-N`。只有直接点击顶部模式按钮时，第一人称才从当前水平航向开始。

## 碰撞边界

PlayCanvas 官方 GS 第一人称示例并不只是相机脚本：它加载 Ammo、独立碰撞 GLB、胶囊碰撞体和动态刚体，
并包含落地检测、重力与跳跃。当前系统复用该示例的 `KeyboardMouseSource`、鼠标视角公式以及水平航向
WASD 公式；由于当前视角代表空中飞行器而不是地面行人，移动载体改为同一个相机的无刚体位移，并增加
Q/E 世界高度控制。没有复制 Shader，也没有启动另一套 Renderer。

系统已经拥有后端 SVO 碰撞真值，航线规划当前使用的是各向同性膨胀球及连续扫掠。它不等于前端逐帧
飞行碰撞，也不等于 `0.30 × 0.30 × 0.15 m` 的精确机体：半径 0.15m 的膨胀球可以作为保守近似，
但会把竖直方向也扩到 0.15m。若实现精确飞行器碰撞，应新增独立的机体尺寸/安全余量数据契约及 SVO
扫掠体，而不是使用官方行人控制器的落地、重力和跳跃。飞行器不受地面约束，但地面实体仍应作为障碍，
防止穿模。视觉 GS 深度和调试 GLB 都不能替代航线安全真值。
